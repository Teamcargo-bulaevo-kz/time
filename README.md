# TIME — Smart Wake

Android-приложение будильника с постепенным звуковым и световым пробуждением, проверкой бодрствования и возможностью интеграции с голосовым ассистентом Frend («Пятница»).

 > Текущий статус: прототип этапов 1–3. Реализованы будильники, звуковые профили, вспышка, вибрация, проверка пробуждения и экран срабатывания. Сборка и физическое тестирование последних изменений ещё должны быть подтверждены.

## Цели проекта

1. Оставаться простым обычным будильником: создать будильник за несколько нажатий, выбрать время, дни недели и мелодию.
2. Надёжно срабатывать при выключенном экране и в Doze-режиме Android, насколько это позволяют системные API и настройки производителя.
3. Поддерживать постепенное нарастание звука: дождь, гроза, музыка и собственные аудиофайлы.
4. Использовать экран, вспышку камеры и вибрацию как дополнительные сигналы.
5. После временного отключения звука запускать задачу на пробуждение (таблица Шульте, математика, память, моторика); затем повторять проверку через заданный интервал, по умолчанию 5 минут.
6. Давать пользователю аварийный способ остановить сигнал в любой момент.
7. Иметь стабильный внутренний API, чтобы функции будильника можно было вызывать из Frend без переноса всей логики в ассистент.

## Принципы UX

- Главный экран показывает список будильников и одну заметную кнопку добавления.
- Создание/редактирование: время, дни недели, подпись, звук, громкость, длительность нарастания, свет, вибрация, режим проверки.
- Частые настройки доступны сразу; расширенные — в отдельном разделе.
- Выключенный будильник визуально отличается от включённого.
- Разрешения запрашиваются в момент включения соответствующей функции, а не все сразу.
- Никаких обязательных аккаунтов, облака или подключения к интернету для базового будильника.
- Русский язык — основной для первой версии; строки интерфейса хранятся в ресурсах.

## Основной сценарий пробуждения

1. В заданное время запускается экран будильника, звук, вибрация и выбранные световые сигналы.
2. Пользователь может выбрать «Отложить» (обычный snooze) или «Отключить звук и пройти проверку».
3. При выборе проверки звук прекращается, открывается случайное задание.
4. После правильного решения приложение фиксирует успешное прохождение и запускает контрольный таймер (по умолчанию 5 минут).
5. Если контроль не подтверждён, будильник повторяется с новым заданием.
6. Пользователь всегда может воспользоваться отдельной аварийной кнопкой остановки. Аварийная остановка прекращает звук/вспышку и помечает событие как прерванное; она не считается успешным подтверждением пробуждения.

Задания первой очереди:
- Таблица Шульте 5×5 с новой случайной перестановкой на каждый запуск.
- Простые арифметические примеры с настраиваемой сложностью.
- Поиск/сопоставление символов и короткие последовательности памяти.
- Лабиринт или точное касание целей для мелкой моторики.
- Опционально: QR-код в другой части комнаты. Это дополнительный режим, не обязательный для работы приложения.

## Звук и свет

- Профили звука: «Дождь», «Гроза», «Музыка», «Мой файл».
- Плавное увеличение громкости с настраиваемыми начальным/конечным уровнями и длительностью.
- Переходы без резких скачков; микширование дождя/грома и музыки — отдельная настройка.
- Свет: плавное увеличение яркости экрана; вспышка камеры только после явного разрешения и с ограничением частоты.
- Вибрация настраивается отдельно.
- Звук должен корректно останавливаться при аварийном выключении, завершении проверки, звонке/аудиофокусе и системном завершении процесса.

## Мониторинг сна — ограничения

Оценка момента засыпания может использовать локальные сигналы телефона (движение, взаимодействие, звук окружающей среды только при отдельном согласии) и данные совместимого браслета, если доступен поддерживаемый API.

Приложение не обещает медицински точное определение фаз сна. Телефон и потребительские браслеты не измеряют фазы сна напрямую с клинической точностью. Цикл 90 минут — лишь приблизительная эвристика. Продолжительность сна и заданное пользователем крайнее время пробуждения важнее попытки попасть в предполагаемую фазу.

Адаптивное окно пробуждения не должно переносить будильник за установленный пользователем крайний срок. Если достоверных данных нет, срабатывает обычное заданное время.

## Архитектура

Первая версия — нативный Android-проект на Kotlin и Jetpack Compose, с разделением по слоям и границам модулей:

- app — точка входа, навигация, экраны и связывание зависимостей.
- core:model — модели будильников, расписаний, задач и событий.
- core:alarm — планирование точных срабатываний, восстановление расписания после перезагрузки.
- core:audio — воспроизведение, плавная громкость, аудиофокус.
- core:wakecheck — задания и проверка результата.
- core:sensors — локальная оценка активности и адаптеры носимых устройств.
- core:integration-api — стабильные контракты для внешнего ассистента.
- feature:alarms — список и редактор будильников.
- feature:ringing — экран срабатывания и управление сигналом.
- feature:wakecheck — интерактивные задания.
- feature:sleep — журнал и оценка сна.

На раннем этапе допускается физически один Android-модуль с пакетами по этим границам. Выделять Gradle-модули следует, когда интерфейсы стабилизируются. Это уменьшает начальную сложность, не мешая последующему выделению библиотек.

### Интеграция с Frend

Интеграция не должна зависеть от внутреннего UI приложения. Контракт integration-api будет описывать операции:
- получить список будильников;
- создать, изменить, включить или отключить будильник;
- запросить ближайшее срабатывание;
- получить состояние активного сигнала;
- открыть экран настройки или активного будильника.

Предпочтительный путь первой интеграции — явные Android Intents с проверкой вызывающего приложения и документированными параметрами. Для более тесной связи позже можно добавить отдельную Android-библиотеку/API и Binder service. Не запускать скрытые действия без согласия пользователя. Ассистент не должен иметь возможности обходить аварийное отключение.

## Надёжность Android

- Для точного времени использовать AlarmManager и проверять доступность exact alarms на версии Android устройства.
- Для активного звучания использовать foreground service с корректным типом службы и уведомлением.
- После перезагрузки восстанавливать расписание через BOOT_COMPLETED, если пользователь разрешил нужные возможности.
- Учитывать ограничения фонового запуска Activity, Doze, энергосбережение и OEM-ограничения Xiaomi.
- Не полагаться на постоянно работающий фоновый процесс или таймер в памяти.
- Проверить поведение после принудительной остановки приложения: Android может блокировать автоматический запуск до следующего ручного открытия.
- Не обещать абсолютную гарантию срабатывания: системные ограничения, отключённые разрешения, разряженная батарея и принудительная остановка могут помешать.

- Kotlin

Конкретные версии зависимостей фиксируются при создании сборки и проверяются совместно.

## Правила разработки

1. Не менять работающие функции без отдельной причины и теста.
2. Каждый этап — отдельный небольшой коммит.
3. Не смешивать UI, расписание, аудио и интеграцию в одном классе.
4. Все фоновые действия должны иметь явное состояние и корректно завершаться.
5. Сначала надёжность обычного будильника, затем интеллектуальные функции.
6. Не добавлять разрешения без необходимости.
7. Документировать ограничения Android и фактические результаты тестов; не выдавать запланированное за реализованное.
